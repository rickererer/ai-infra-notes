# 2026-10-23 张量的构造与数据预处理

对应 d2l 的 2.1 数据操作、2.2 数据预处理。今天在 JupyterLab 里逐格敲，遇到两处教材与新版 pandas 的冲突。

## 一个 1.0 决定整个张量的类型

```python
torch.tensor([1, 2, 4, 8]).dtype      # torch.int64
torch.tensor([1.0, 2, 4, 8]).dtype    # torch.float32
```

列表里只要有一个浮点数，整个张量就是 float32。`torch.tensor` 从数据推断类型，不默认 float。

默认 float32 的是另外两个：

| 写法 | dtype 怎么定 |
|---|---|
| `torch.tensor([...])` | 看数据，有浮点就 float32 |
| `torch.zeros(3)` / `ones(3)` | 固定 float32，不看输入 |
| `torch.arange(12)` | 看参数，整数参数给 int64 |

这也解释了为什么 `zeros` 打印出来是 `tensor([0., 0., 0.])`，而 `arange` 是 `tensor([0, 1, 2])`。

## int64 的限制在函数上，不在运算符上

`mean` 和 `norm` 会直接报错：

```
RuntimeError: mean(): could not infer output dtype.
Input dtype must be either a floating point or complex dtype

RuntimeError: linalg.vector_norm: Expected a floating point
or complex tensor as input. Got Long.
```

但除法没问题：

```python
torch.tensor([1,2,4,8]) / sum      # float32, [0.0667, 0.1333, 0.2667, 0.5333]
```

`/` 是真除法，除完自动转浮点。所以整数张量不是"什么都不能算"，是那几个统计函数在拦你。

按 d2l 的做法写 `1.0` 是个隐式手段，更明确的写法是 `dtype=torch.float32` 或 `.float()`。

## 屏幕上看到的不是数据本身

```python
x = torch.tensor([1.0, 2, 4, 8]) / 15

x              # tensor([0.0667, 0.1333, 0.2667, 0.5333])
x[0].item()    # 0.06666667014360428
```

四位小数是 `print` 的排版，内存里存的是完整的 float32。`torch.set_printoptions(precision=10)` 能看更多，但也到 `0.0666666701` 就停了，那是 float32 的精度上限。

有个坑：**相邻数值太近时不会自动加位数**。

```python
torch.tensor([1.00001, 1.00002, 1.00003])
# tensor([1.0000, 1.0000, 1.0000])
```

三个不同的数显示成一样。判断相等只能用 `==` 或 `torch.allclose`，看输出看不出来。

数值跨度大时会自动切科学计数法：

```python
torch.tensor([0.0000123, 12345.0])
# tensor([1.2300e-05, 1.2345e+04])
```

`12345.0` 本来能完整显示，被旁边那个小数拖累成科学计数法。不想这样就 `torch.set_printoptions(sci_mode=False)`。

## exp 的上限在 88

```python
torch.exp(torch.tensor([0.0, 1.0, 2.0, 3.0]))
# tensor([ 1.0000,  2.7183,  7.3891, 20.0855])
```

float32 最大约 `3.4e38`，而 `exp(88)` 约 `1.65e38`，`exp(89)` 直接变 `inf`。

`inf` 进入后续计算会产生 `nan`，因为 `inf / inf = nan`。整条链就废了。

所以 softmax 的实现里都有一句 `x - x.max()`。原理是平移不变性：

```python
a = [1, 2, 3]
exp(a)           # [ 2.7183,  7.3891, 20.0855]
exp(a - a.max()) # [ 0.1353,  0.3679,  1.0000]
```

两组数不同，但两两的比值一样，做除法之后结果完全一致。减完之后最大的一项是 `exp(0) = 1`，其余都小于 1，不可能溢出。

## 轴就是维度的编号

嵌套列表的层数等于 ndim，每一层的长度等于那一维的大小。

```python
x = torch.tensor([[2, 1, 4, 3], [1, 2, 3, 4], [4, 3, 2, 1]])
x.shape    # (3, 4)
x.ndim     # 2
```

数法：最外层有 3 个子列表，对应轴 0 长度 3；每个子列表有 4 个数，对应轴 1 长度 4。

索引可以反过来验证：

```python
x[0]      # tensor([2, 1, 4, 3])   取轴 0 的第 0 个，拿到一整行
x[0, 1]   # tensor(1)              取到单个元素
x[:, 1]   # tensor([1, 2, 3])      轴 0 全要，轴 1 只要第 1 个
```

"沿某个轴操作"的意思是把那个轴上的元素合并掉，该轴从 shape 里消失。所以 `x.sum(axis=1)` 把 `(3,4)` 变成 `(3,)`。

## 连接和堆叠的约束不一样

`cat` 除连接轴之外，其余维度必须一致，维度数也必须一致：

| 操作 | 结果 |
|---|---|
| `cat((a(3,4), c(2,4)), dim=0)` | `(5, 4)`，轴 0 可以不同 |
| `cat((a(3,4), d(2,3)), dim=0)` | 报错，轴 1 一个 4 一个 3 |
| `cat((a(3,4), x(4,)), dim=0)` | 报错，维度数 2 和 1 |

二维拼一维要先加一维：

```python
torch.cat((a, torch.arange(4).unsqueeze(0)), dim=0)   # (1,4) 之后能拼
```

`stack` 要求所有形状完全相同，结果在最前面多一个轴：

```python
torch.stack((a(3,4), b(3,4)))    # (2, 3, 4)
```

一句话区分：`cat` 是接长，轴数不变；`stack` 是叠起来，轴数加一。

## 广播

规则是从尾部对齐，逐维比较：

1. 相等，通过
2. 有一个是 1，那个 1 拉伸成对方的大小
3. 维度数不够的，在前面补 1
4. 都不满足，报错

`a(3,1) + b(1,2)` 的过程：

```
轴 1：1 和 2 → 1 拉成 2
轴 0：3 和 1 → 1 拉成 3
结果：(3, 2)
```

算的时候相当于：

```
a 变成 [[0,0],[1,1],[2,2]]
b 变成 [[0,1],[0,1],[0,1]]
相加   [[0,1],[1,2],[2,3]]
```

**内存里不真的复制。** 实测 `b.expand(3,2)`：

```
stride  : (0, 1)
底层存储: 2 个元素        逻辑上是 6 个
连续    : False
```

stride 第一位是 0，表示沿轴 0 前进一行时内存不动，反复读同一块。代价是结果非连续，后面某些操作要 `.contiguous()`。

报错的样子：

```
torch.ones(3,1) + torch.ones(2,2)
→ The size of tensor a (3) must match the size of tensor b (2)
  at non-singleton dimension 0
```

`non-singleton` 意思是"不是 1 的那一维"。

**keepdim 的坑。** 求完均值想减回去时形状会塌：

```python
x.mean(dim=1).shape                     # (3,)
x.mean(dim=1, keepdim=True).shape       # (3,1)

x - x.mean(dim=1)                       # 报错或错位
x - x.mean(dim=1, keepdim=True)         # 每行减自己的均值，正确
```

`(3,4)` 减 `(3,)`，后者被当作 `(1,3)`，和 4 对不上。凡是压缩某一维再广播回去的场景，都要加 `keepdim=True`。

## 2.2 数据预处理

### 建目录要先判断存在

```python
os.makedirs(os.path.join('..', 'data'), exist_ok=True)
```

不加 `exist_ok` 的话，第二次运行这一步直接抛 `FileExistsError: [WinError 183] 当文件已存在时，无法创建该文件`，后面一行都跑不到。

`exist_ok` 只影响报不报错，**不清空已有目录里的东西**。

`mkdir` 只能建一层，父目录不存在会 `FileNotFoundError`；`makedirs` 递归建。

### CSV 的列名是读出来的，不是写出来的

```python
f.write('NumRooms,Alley,Price\n')
f.write('NA,Pave,127500\n')
```

`write` 只往文件里塞字符串，文件内容就是纯文本：

```
'NumRooms,Alley,Price\nNA,Pave,127500\n2,NA,106000\n'
```

没有任何元数据说哪一行是列名。`pd.read_csv` 默认 `header=0`，把第 0 行当列名。换 `header=None` 看看：

```
默认：            语义：
   NumRooms Alley   Price      0  NumRooms  Alley   Price
0       NaN  Pave  127500      1       NaN   Pave  127500
1       2.0   NaN  106000      2         2    NaN  106000

                              列名变成 0,1,2
```

同一份文件两种读法。d2l 先写字段名，是配合 `read_csv` 的默认行为，不是"第一行天生是表头"。

`f.write` 不自动加换行，每行末尾的 `\n` 必须自己写。`print` 会自动加，这两个不一样。

### NA 自动变成 NaN

`read_csv` 的 `na_values` 预置了一批字符串：`NA`、`NaN`、`null`、`N/A` 等，遇到就转成缺失值。d2l 用 `NA` 表示缺失正好利用这一点。

如果数据里有个正常字符串恰好叫 NA，用 `keep_default_na=False` 关掉。

## pandas 2.x 和教材的两处冲突

本机 pandas 2.2.3。d2l 的代码写于 1.x，两处默认值改了。

### 一、mean 报 TypeError

```python
inputs = inputs.fillna(inputs.mean())
# TypeError: can only concatenate str (not "int") to str
```

`inputs` 里 `NumRooms` 是 float64，`Alley` 是 object（字符串）。pandas 2.0 把 `numeric_only` 的默认值改成 `False`，不再自动跳过非数值列，于是它去给字符串求均值，变成了字符串拼接。

改法：

```python
inputs = inputs.fillna(inputs.mean(numeric_only=True))
```

结果：

```
   NumRooms Alley
0       3.0  Pave
1       2.0   NaN
2       4.0   NaN
3       3.0   NaN
```

`mean(numeric_only=True)` 返回的 Series 只有 NumRooms 一项，`fillna` 按列名对齐时 Alley 找不到对应值，保持原样。这正好是想要的：数值缺失用均值补，类别列留给后面处理。

### 二、get_dummies 的类型变了

pandas 1.x 返回 `uint8`，和 float64 混合后被提升成 float64，`torch.tensor(df.values)` 能跑。

pandas 2.x 返回 `bool`，和 float64 混在一起 numpy 只能降级成 `object`：

```
TypeError: can't convert np.ndarray of type numpy.object_
```

改法：

```python
X = torch.tensor(inputs.to_numpy(dtype='float32'))
# tensor([[3., 1., 0.],
#         [2., 0., 1.],
#         [4., 0., 1.],
#         [3., 0., 1.]])
```

### dummy_na 在做什么

`get_dummies` 把类别列拆成 0/1 指示列，这样模型才能处理。

不加 `dummy_na`：

```
   NumRooms  Alley_Pave
1       2.0       False       ← 缺失被编码成全 0
```

模型看到的是一个合法取值，分不清"值不是 Pave"和"值缺失"。

加 `dummy_na=True`：

```
   NumRooms  Alley_Pave  Alley_nan
1       2.0       False       True   ← 缺失单独标出来
```

"没登记"本身可能携带信息（房主没填，往往说明房子状况特殊），所以要单独一列。

## 概念清单

### 张量与类型

| 概念 | 含义 |
|---|---|
| dtype 推断 | `torch.tensor` 从数据的元素类型推断；有一个浮点就是 float32，全整数是 int64。`zeros` / `ones` 不看输入，固定 float32 |
| float32 / int64 | 前者 4 字节带小数，后者 8 字节整数。float32 尾数 23 位，约 7 位十进制有效数字，最大约 3.4e38 |
| `.item()` | 从单元素张量取出 Python 数字，返回完整精度（如 0.06666667014360428），不受打印精度影响 |
| 打印精度 | 显示用的小数位数，默认 `precision=4`。改法 `torch.set_printoptions(precision=10)`。只是排版，不改数据 |
| `torch.exp` | 逐元素算 `e^x`。float32 下 `exp(88)` 约 1.65e38 仍有效，`exp(89)` 溢出成 `inf` |
| `inf` / `nan` | 无穷大和非法值。溢出产生 inf，`inf/inf` 或 `inf-inf` 产生 nan，之后整条计算链都不可用 |

### 形状与索引

| 概念 | 含义 |
|---|---|
| `ndim` / `shape` | ndim 是维度数（嵌套列表的层数），shape 是每一维的长度。`(3,4)` 表示 3 行 4 列 |
| 轴 axis | 维度的编号，从 0 开始。轴 0 是行方向，轴 1 是列方向。沿某轴操作 = 合并该轴元素，该轴从 shape 消失 |
| `.iloc[]` | 按位置取，不按标签。`data.iloc[:, 0:2]` 取所有行的前两列，`data.iloc[:, 2]` 取第 3 列 |
| `unsqueeze(n)` | 在第 n 个位置插一个长度为 1 的维度。`(4,)` 变 `(1,4)`，用于让维度数对齐才能 `cat` |

### 连接与广播

| 概念 | 含义 |
|---|---|
| `torch.cat` | 沿已有维度接长，轴数不变。除连接轴外所有维度必须相等，维度数也必须相等 |
| `torch.stack` | 在新维度上叠，轴数加一。要求所有张量形状完全相同：两个 `(3,4)` 得到 `(2,3,4)` |
| 广播 | 从尾部对齐逐维比较：相等通过；有 1 则拉伸成对方大小；维度不够前面补 1；否则报错 |
| stride | 索引每加 1 在内存里跳几个元素。广播时把对应维度的 stride 设成 0，实现"逻辑复制、物理不复制" |
| `keepdim=True` | 归约时保留被压缩的维度为长度 1。`(3,4)` 按 dim=1 求均值，不加得到 `(3,)`，加了得到 `(3,1)` |

### pandas 预处理

| 概念 | 含义 |
|---|---|
| `exist_ok=True` | 目录已存在时不抛 `FileExistsError`。只影响报错，不清空已有内容 |
| `header` | `read_csv` 决定哪一行当列名。默认 `header=0` 取第 0 行；`header=None` 则第 0 行变成数据，列名自动编号 0,1,2 |
| `na_values` | 被当作缺失值的字符串列表，默认含 `NA`、`NaN`、`null`、`N/A`。关掉用 `keep_default_na=False` |
| `fillna(x)` | 用 x 填缺失值。x 是 Series 时按列名对齐，对不上的列保持原样 |
| `numeric_only=True` | 让 `mean` / `sum` 等只处理数值列。pandas 2.0 起默认 `False`，不加会去算字符串列并报 TypeError |
| `get_dummies` | 把类别列展开成 0/1 指示列（one-hot）。pandas 2.x 返回 `bool`，1.x 返回 `uint8` |
| `dummy_na=True` | 把缺失值也当成一个类别单独出一列。不加的话缺失会被编码成全 0，无法与"不属于任何类别"区分 |
| one-hot 编码 | 把 n 个取值展开成 n 列，每行只有一列为 1。目的是把类别变成数字，模型只能处理数字 |
