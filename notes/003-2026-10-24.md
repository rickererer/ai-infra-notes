对应 d2l 2.3 线性代数、2.4 微积分。第 2 章到此结束。

## 沿某个轴求和，那个轴就消失

`A` 是 5 行 4 列：

```python
A = torch.arange(20, dtype=torch.float32).reshape(5, 4)

A.sum(axis=0)   # tensor([40., 45., 50., 55.])      shape (4,)
A.sum(axis=1)   # tensor([ 6., 22., 38., 54., 70.])  shape (5,)
```

`40` 是第一列的五个数相加：`0+4+8+12+16`。

教材那句「求和所有行的元素来降维（轴 0）」容易读成「对每一行求和」，那样会得到 `axis=1` 的结果。它实际说的是**跨过所有行，把同一列的加起来**。

`axis=0` 是沿着轴 0 的方向走，也就是竖着穿越 5 行，把每一列压成一个数。

## 形状的变化可以死记

```
(5, 4)  sum(axis=0)  →  (4,)     删掉第 0 个数
(5, 4)  sum(axis=1)  →  (5,)     删掉第 1 个数
```

**axis=k 就是把 shape 里第 k 个数删掉。** 三维一样：

```python
x = torch.zeros(2, 3, 4)
x.sum(axis=1).shape   # (2, 4)   删掉中间的 3
x.sum(axis=2).shape   # (2, 3)   删掉最后的 4
```

不是「减 1」，是那一维整个不见。5 行消失后结果是一维向量，不是 1 行 4 列。

想留住这一维就给 `keepdim`：

```
A.sum(axis=0)                → (4,)
A.sum(axis=0, keepdim=True)  → (1, 4)
```

数值完全一样，只是形状不同。`(1,4)` 可以直接和 `(5,4)` 相减，而 `(4,)` 会被当作 `(1,4)`，有时候会算错。

## 不是所有带 axis 的操作都降维

```python
A.cumsum(axis=0).shape    # (5, 4)   形状不变
```

`cumsum` 是累加，每一行仍然要有输出值，所以轴 0 保留。

判断方法看操作本身：**归约类（sum、mean、max、norm）消掉那一维，逐元素类（cumsum、sort、softmax）不会。**

## grad_fn 是计算图的入口

```python
x = torch.arange(4.0)
x.requires_grad_(True)
y = 2 * torch.dot(x, x)
y
# tensor(28., grad_fn=<MulBackward0>)
```

`grad_fn` 告诉 PyTorch 反向时用哪种求导规则。拆开读：

```
Mul        产生这个张量的运算是乘法
Backward   对应的反向求导函数
0          同名实例的序号，一般不用管
```

为什么是 `Mul`：`y = 2 * torch.dot(x, x)` 最外层运算是乘 2。`dot` 那一步也记着，藏在下一层：

```python
y.grad_fn.next_functions
# ((<DotBackward0 object>, 0), (None, 0))
```

第二个是 `None`，因为常数 `2` 不需要求导，是叶子节点。顺着 `next_functions` 往回走就能走到 `x`，`backward()` 干的就是这件事。

验证这张图没记错：

```python
y.backward()
x.grad    # tensor([ 0.,  4.,  8., 12.])
```

`y = 2 * Σxᵢ²`，导数是 `4xᵢ`，代入 `[0,1,2,3]` 正好。

## grad_fn 什么时候是 None

两种：

**叶子节点。**

```python
x = torch.arange(4.0, requires_grad=True)
x.grad_fn    # None
```

`x` 是直接创建的，不是算出来的，它只是图的起点。

**没打开梯度追踪。**

```python
x2 = torch.arange(4.0)
y2 = 2 * torch.dot(x2, x2)
y2.grad_fn   # None
```

`x2.requires_grad` 是 False，整条链不建图。

这个属性最实用的地方是调试梯度：print 一下 `grad_fn`，看到 `None` 就说明梯度到不了这里，前面某处被切断了。

## backward 只能从标量开始

```python
x = torch.arange(4.0, requires_grad=True)
y = x * x          # tensor([0., 1., 4., 9.])  四个元素
y.backward()
```

报错：

```
RuntimeError: grad can be implicitly created only for scalar outputs
```

翻译过来：只有标量输出能自动创建梯度。

原因是反向传播需要一个起点值。`loss` 是标量，自己对自己求导是 1，天然有起点。`y` 是向量，PyTorch 不知道第一站该发几个数字出去。

## 两种绕法，本质是一件事

```python
y.sum().backward()                  # x.grad = [0., 2., 4., 6.]
y.backward(torch.ones(4))           # x.grad = [0., 2., 4., 6.]
```

`sum` 对每个 `yᵢ` 的导数都是 1，所以它等于发一串 1 下去。

走一遍数字：

| 走到哪 | 收到什么 | 本地导数是 | 传下去 |
|---|---|---|---|
| sum | 1 | 全都是 1 | `[1,1,1,1]` |
| 平方 | `[1,1,1,1]` | `2x = [0,2,4,6]` | `[0,2,4,6]` |

**规则只有一条：回来的箭头，每一站把收到的数乘上自己这一步的导数。**

## gradient 参数是每个位置的权重

```python
x.grad.zero_()
y = x * x
y.backward(torch.tensor([0., 1., 0., 0.]))
x.grad
# tensor([0., 2., 0., 0.])
```

只有第二个位置有梯度。因为只有它的起始数字是 1，其他位置发的是 0，0 乘任何数还是 0。

换成权重 `[1,2,3,4]`：

```python
y.backward(torch.tensor([1., 2., 3., 4.]))
# x.grad = [ 0.,  4., 12., 24.]   就是 2x 逐位乘上权重
```

所以 `gradient` 的意思是这个元素在最终目标里占多大分量。填 1 就是每个元素一样重要。

## detach 把数据从图上摘下来

```python
x = torch.arange(4.0, requires_grad=True)
y = x * x
u = y.detach()
z = u * x
z.sum().backward()
x.grad == u
# tensor([True, True, True, True])
```

实测两个事实：

```
u.grad_fn   → None             切断了，不再是图的一部分
共享内存    → True             u 和 y 用同一块内存，没有复制
```

所以 `z = u * x` 对 `x` 求导时，`u` 被当常数，导数就是 `u` 本身，`[0,1,4,9]`。

对比不 detach：

```python
z2 = y * x        # y = x²，所以 z2 = x³
z2.sum().backward()
x2.grad    # tensor([ 0.,  3., 12., 27.])   就是 3x²
```

同一份数据，detach 之后导出 `[0,1,4,9]`，不 detach 导出 `[0,3,12,27]`。差别就在于它还是不是 x 的函数。

实际用途两个：

```python
p.detach_()                        # 冻结参数，不再更新
loss_value = loss.detach().item()  # 只取数值，不把计算图留在内存里
```

第二种写训练循环时天天用。不加 `detach`，那个 loss 会把整条计算图留着，跑几千步就爆显存。

## 概念清单

### 归约与形状

| 概念 | 含义 |
|---|---|
| 归约 reduction | 把多个元素合并成一个或少数几个的运算。sum、mean、max、norm 都是，结果会少一个维度 |
| axis | 沿哪个方向做运算。`axis=0` 是竖着跨行，`axis=1` 是横着跨列。`axis=k` 等价于删掉 shape 里第 k 个数 |
| keepdim | 归约时保留那一维为长度 1。`(5,4)` 按 axis=0 求和，不加得 `(4,)`，加了得 `(1,4)` |
| cumsum | 累加，前 i 个元素之和放在第 i 位。形状不变，因为每个位置都要有输出 |
| 逐元素操作 | 元素个数不变的运算，如 cumsum、sort、softmax、加减乘除 |

### 计算图

| 概念 | 含义 |
|---|---|
| 计算图 | 记录每个张量由什么运算、什么输入算出来的有向无环图。前向时自动建，反向时沿着它倒着走 |
| grad_fn | 张量上的属性，指向产生它的那个反向函数节点。`<MulBackward0>` 表示由乘法产生。None 表示它不在图里 |
| MulBackward0 | 拆开是 Mul（乘法）、Backward（反向求导）、0（同名实例序号）。对应 y = 2 * dot(x,x) 里最外层的乘 2 |
| next_functions | grad_fn 上的属性，指向上一层节点。`((DotBackward0, 0), (None, 0))` 里 None 表示那一支是常数 |
| 叶子节点 | 用户直接创建的张量，不是运算结果，所以 grad_fn 为 None。它只是图的起点 |
| requires_grad | 是否记录梯度。False 时整条链不建图，结果的 grad_fn 也是 None |

### 反向传播

| 概念 | 含义 |
|---|---|
| 标量输出限制 | `backward()` 要求输出是单个数值。因为反向需要一个起始梯度，标量自己对自己求导是 1，向量没有这个天然起点 |
| gradient 参数 | 非标量输出时必须传，给出每个位置的起始梯度（上游梯度）。填 1 表示每个元素等权，填 0 表示该位置不算 |
| 链式传递 | 反向时每一站把收到的梯度乘上本地导数再往下传。sum 的导数是 1，平方的导数是 2x |
| detach | 返回值相同、共享同一块内存，但 grad_fn 为 None，从此不参与梯度计算，求导时被当常数 |
| 不 detach 的后果 | 若 z = y * x 且 y = x²，则 z = x³，导数是 3x²。detach 之后 y 变常数，导数退化成 y 本身 |
