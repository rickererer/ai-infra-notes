# 2026-10-26 线性回归的简洁实现

对应 d2l 3.3。同一件事，用 `nn` 和 `DataLoader` 重写 3.2 的手写版。

## 一行 `*` 解包

```python
dataset = data.TensorDataset(*data_arrays)
```

`data_arrays` 是元组 `(features, labels)`。`*` 把它拆成两个位置参数，等价于 `TensorDataset(features, labels)`。写成 `TensorDataset(data_arrays)` 会错，那是把元组当成了一个张量参数。

## TensorDataset 只有四行是干活的

源码可以直接看：

```python
class TensorDataset(Dataset):
    def __init__(self, *tensors):
        assert all(tensors[0].size(0) == tensor.size(0) for tensor in tensors)
        self.tensors = tensors

    def __getitem__(self, index):
        return tuple(tensor[index] for tensor in self.tensors)

    def __len__(self):
        return self.tensors[0].size(0)
```

它没做任何计算。`__getitem__(i)` 返回 `(features[i], labels[i])`，`__len__` 返回样本数。作用就是把几个张量按行对齐，让你能用 `dataset[i]` 一次拿到一条样本的所有字段。

## 第一维必须一致，只查这一维

`assert` 那行检查的是 `size(0)`，也就是样本数。

```python
features (1000, 2)  +  labels (1000, 1)   合法
features (1000, 2)  +  labels (900, 1)    AssertionError: Size mismatch between tensors
```

原因是它取样本靠 `tensor[index]`，索引作用在第一维上。第一维对不上，索引到 950 时 labels 那边就不存在了。

**后面几维可以随便不同**，因为那是“一条样本长什么样”。图像场景更能说明：

```python
images (1000, 1, 28, 28)  +  labels (1000,)   合法
dataset[0] → (一张 (1,28,28) 的图, 标签)
```

第一维是“有几条”，其余维是“一条多复杂”。`TensorDataset` 只关心前者。

这里用的是 `assert` 而不是抛异常，意思是“这是调用者该保证的前提”，不是运行时需要处理的错误。

## DataLoader 替掉了手写的四步

```python
indices = list(range(1000))
random.shuffle(indices)                      # shuffle=True 时做
for i in range(0, 1000, 32):
    batch_indices = indices[i:i+32]          # 切批
    yield features[batch_indices], labels[batch_indices]   # 花式索引
```

换成 `DataLoader` 之后批数和形状完全一致：32 批，前 31 批各 32 个，最后一批 8 个，单批形状 `(32,2)` 和 `(32,1)`。

内部多出来的能力是 sampler、多进程预取、自定义采样。

**`shuffle=is_train` 是一个函数两用。** 实测区别：

```
is_train=False  两次取的第一批相同，就是原始前 32 行
is_train=True   两次取的第一批不同
```

评估时必须保序，一是结果可复现，二是能对上“第几个样本错了”。

两个常用参数：

```python
DataLoader(dataset, batch_size=32, shuffle=True,
           num_workers=4,      # 多进程预取
           drop_last=True)     # 丢掉最后不满一批的
```

`num_workers` 在 Windows 上设大了容易出问题，因为子进程要重新 import 主模块，脚本没有 `if __name__ == '__main__':` 保护会反复执行。数据在内存里时设 0 就行。

## MSELoss 的三种 reduction

```python
nn.MSELoss()                    # 默认 mean
nn.MSELoss(reduction='sum')
nn.MSELoss(reduction='none')
```

误差 `[0.5, 0.5, -1.0]` 的实测：

| reduction | 形状 | 值 |
|---|---|---|
| `mean` | `()` 标量 | 0.5 |
| `sum` | `()` 标量 | 1.5 |
| `none` | `(3,1)` | `[0.25, 0.25, 1.0]` |

`none` 用在要给每个样本单独加权的场景，比如 focal loss。

## 一个会静默算错的坑：形状广播

`MSELoss` 不检查形状，直接交给广播。

```python
y_hat  (4, 1)
y      (4,)
```

它把两个张量广播成 `(4,4)`，算了 16 对误差而不是 4 对。loss 出来 `0.6347`，正确值应该是 `0.8971`。

PyTorch 其实警告了：

```
UserWarning: Using a target size (torch.Size([4])) that is different to
the input size (torch.Size([4, 1])). This will likely lead to incorrect
results due to broadcasting.
```

**这条 warning 必须看。** 它不中断训练，loss 照常下降，但算的是错的东西，最后模型效果莫名变差。

正确写法是显式对齐：

```python
loss = nn.MSELoss()(y_hat, y.reshape(y_hat.shape))
```

3.2 手写版里的 `squared_loss` 就有这么一句，不是多余的。

## 和手写版差一个 2 倍常数

3.2 的 `squared_loss` 末尾有 `/ 2`，`nn.MSELoss()` 没有。实测比值正好 2.0。

所以两者的梯度也差 2 倍。教材两节都写 `lr = 0.03`，**实际等效学习率差了一倍**，3.3 那节步子更大。

这个差异不影响收敛，但拿两版做对比实验时要意识到不是同一个损失尺度。

`/2` 的来源是求导方便，`(x²/2)' = x`，省掉系数 2。

## 训练循环的两层结构

```python
for epoch in range(num_epochs):
    for X, y in data_iter:          # 内层：每批更新一次参数
        l = loss(net(X), y)
        trainer.zero_grad()
        l.backward()
        trainer.step()
    l = loss(net(features), labels) # 外层结束：全量评估一次
    print(f'epoch {epoch + 1}, loss {l:f}')
```

外层一个 epoch 过一遍数据集，内层每批更新一次。1000 样本 batch=10，一个 epoch 更新 100 次。

三个方法和手写版的对应：

| 简洁版 | 3.2 手写版 |
|---|---|
| `trainer.zero_grad()` | `for p in params: p.grad.zero_()` |
| `trainer.step()` | `for p in params: p -= lr * p.grad / batch_size` |
| `SGD(net.parameters(), lr)` | 手动传参数列表加 lr |

`trainer.step()` 里不用除 batch_size，因为 `MSELoss` 默认算平均，梯度已经是平均梯度。

实测跑完 3 轮：

```
epoch 1, loss 0.000247
epoch 2, loss 0.000093
epoch 3, loss 0.000094

w = [1.9997, -3.3988]    真值 [2.0, -3.4]
b = 4.2002               真值 4.2
```

误差千分之一以内。这是用合成数据的价值：能直接比参数，不只看 loss。

## 教材这里有两处可以改

**一、评估没加 `no_grad`**

```python
l = loss(net(features), labels)
```

实测这行的 `l.requires_grad` 是 `True`，说明整条前向都被记进了计算图，但后面不会 `backward()`，白建。数据小看不出问题，习惯要养好：

```python
with torch.no_grad():
    l = loss(net(features), labels)
```

改完变成 `False`。

**二、打印的是训练集 loss**

`features`、`labels` 就是训练用的那批，所以这只能叫 train_loss，看不出泛化能力。教材为了简洁省掉了验证集，4.4「模型选择」会补。

## zero_grad 清成 None，不是 0

```python
p.grad                    # tensor([[0.0541, 0.0101], ...])
opt.zero_grad()
p.grad                    # None
```

PyTorch 2.0 起默认 `set_to_none=True`。设 `None` 只改一个引用，写 0 则要给整个张量做 memset，7B 模型的梯度 14 GB，往 14 GB 上写零真的花时间。

想看老行为：

```python
opt.zero_grad(set_to_none=False)
p.grad                    # tensor([[0., 0.], [0., 0.]])
```

两种都能用，因为 `p.grad is None` 时 `backward()` 会新建，是全 0 时会累加。

## optimizer.zero_grad 和 model.zero_grad 不一样

两层网络，优化器**只接管第二层**：

```python
opt = torch.optim.SGD(model[1].parameters(), lr=0.01)
```

反向之后两层都有梯度，然后分别清：

```
optimizer.zero_grad() 后：
  第一层 grad: [[-0.181, 0.294]]   还在
  第二层 grad: None                清了

model.zero_grad() 后：
  第一层 grad: None                也清了
```

**`optimizer.zero_grad()` 只清它 `parameters()` 收到的那些。**

平时没区别，因为谁都把 `model.parameters()` 交给优化器。只有“只优化一部分参数”时才有差别：冻结底层做微调、分参数组、先冻后解冻。

这些场景下用 `optimizer.zero_grad()`，没被优化的层梯度会一直累积。它不参与更新暂时无害，但占显存；一旦解冻，里面躺着几百步前累加的历史梯度，训练直接乱。

所以冻结参数时，要么用 `model.zero_grad()`，要么被冻结的参数本来就设成 `requires_grad=False`（那样根本不产生梯度，也就没有累积）。

## 概念清单

### 数据集封装

| 概念 | 含义 |
|---|---|
| `TensorDataset` | 把多个张量按第一维对齐打包，`dataset[i]` 返回 `(features[i], labels[i])`。只要求各张量 `size(0)` 相同 |
| `DataLoader` | 在 Dataset 外面套一层，负责切批、打乱、多进程预取。内部用 sampler 决定每批取哪些索引 |
| `shuffle=is_train` | 训练时打乱避免顺序偏差；评估时保序，保证结果可复现且能对上具体样本 |
| `num_workers` | 起几个子进程预取数据。Windows 上设大了需要 `if __name__ == '__main__':` 保护，数据在内存时设 0 |
| `drop_last` | 丢掉最后不满一批的样本。用于对批大小敏感的操作，如 batch norm |
| 第一维对齐 | 数据集按 `tensor[index]` 取样本，索引作用于 size(0)。所以只需第一维相同，后面几维可以是任意形状 |

### 损失函数

| 概念 | 含义 |
|---|---|
| `reduction` | 损失怎么归约。`mean` 求平均得标量（默认），`sum` 求和得标量，`none` 保留逐元素输出 |
| 形状广播陷阱 | `(n,1)` 与 `(n,)` 会被广播成 `(n,n)`，算了 n² 对误差。PyTorch 会发 UserWarning，但不中断训练 |
| 与手写版的系数差 | 3.2 的 `(err²/2)` 比 `nn.MSELoss()` 小一倍，等效学习率差 2 倍。`/2` 是为了求导后省掉系数 |

### 训练循环

| 概念 | 含义 |
|---|---|
| `nn.Sequential` | 按顺序串联模块，`net(x)` 依次调用。`net[0]` 可按下标取层，`net.parameters()` 返回所有参数 |
| `trainer.step()` | 优化器按已算好的梯度更新它管理的所有参数。相当于手写版的 `p -= lr * p.grad / bs` |
| `set_to_none` | `zero_grad` 的行为开关。PyTorch 2.0 起默认 True，把 grad 设成 None 而不是写 0，省一次 memset |
| `optimizer.zero_grad` vs `model.zero_grad` | 前者只清优化器接管的参数，后者清模型里全部参数。只优化部分参数时两者行为不同 |
| 梯度累加 | `backward()` 执行 `grad += 新梯度` 而不是赋值。所以必须每轮清零，否则等效学习率随步数上涨 |
