# 2026-10-28 从 softmax 到分类模型的完整实现

对应 d2l 3.4 后半、3.5 数据集、3.6 从零实现、3.7 简洁实现。

## 全连接层：每个输出都看全部输入

数学上就是一次矩阵乘法 `y = Wx + b`。

参数量：

```
参数数 = 输入维度 × 输出维度 + 输出维度
```

| 形状 | 权重 | 偏置 | 合计 |
|---|---|---|---|
| 784 → 10 | 7,840 | 10 | 7,850 |
| 4096 → 4096 | 16,777,216 | 4,096 | 16,781,312 |

三个名字是同一个东西：`nn.Linear`、全连接层、稠密层（dense）。从数学角度还叫仿射层，因为在提 `b`。

**“全”在哪**：权重矩阵每个元素都可以非零，每个输出都能看到全部输入。对比卷积层，每个输出只看输入的一小块。

`784 → 10` 如果只让每个输出连 28 个输入（局部连接），参数量从 `7840` 降到 `280`。**全连接层没有任何结构假设**，这是它表达能力强的原因，也是参数爆炸的原因。

### 小 batch 推理时它很吃亏

`nn.Linear(4096, 4096)` 在 4050 上跑推理，只改 batch：

| batch | 耗时 | FLOPs | 每样本耗时 |
|---|---|---|---|
| 1 | 0.505 ms | 0.03 G | 505 μs |
| 8 | 1.682 ms | 0.27 G | 210 μs |
| 32 | 2.041 ms | 1.07 G | 64 μs |
| 512 | 18.285 ms | 17.2 G | 36 μs |

batch 从 1 涨到 8，计算量涨 8 倍，耗时只涨 3.3 倍。因为每次都要把 67 MB 的权重从显存读一遍，这个成本固定。batch=1 时算力利用率 `0.07 TFLOPS`，卡有 12 TFLOPS，等于用了 0.6%。

**每样本耗时从 505 μs 降到 36 μs，14 倍差距。** 这就是推理服务要做批处理的原因，也是 decode 阶段 memory-bound 的具体表现。

## softmax：把分数变成概率

```
softmax(z)ᵢ = exp(zᵢ) / Σⱼ exp(zⱼ)
```

逐项算一遍，`z = [1.0, 2.0, 3.0]`：

```
exp(z)   = [2.7183, 7.3891, 20.0855]
sum      = 30.1929
softmax  = [0.0900, 0.2447, 0.6652]     加起来 = 1.0
```

三个性质：

**每个输出都是正数。** `exp` 值域 `(0, +∞)`。
**和恒为 1。** 归一化的结果。
**保序。** `exp` 单调递增，谁大谁的概率就大，`argmax` 不变。

### exp 的两个作用

**保正**：直接除以和的话，负数会出负概率。
**放大差距**：

```
z = [1.0, 1.1]  →  [0.475, 0.525]     差 0.1，几乎对半
z = [1.0, 3.0]  →  [0.119, 0.881]     差 2.0，一边倒
```

原始分数差 1 分，概率可能差 10 倍。这个放大效应是 softmax 的核心特征，也是它过自信的根源。

### 数值稳定：减最大值

直接用公式算，大数会溢出：

```
z = [1000, 1001, 1002]
exp(z) = [inf, inf, inf]         float32 上限 3.4e38，早就超了
```

`inf / inf = nan`，整个输出废掉。

做法是给所有元素减掉最大值：

```
z - z.max() = [-2, -1, 0]
exp         = [0.135, 0.368, 1.000]
softmax     = [0.0900, 0.2447, 0.6652]     结果完全一样
```

减完之后最大那个是 `exp(0) = 1`，其余都小于 1，不可能溢出。结果不变是因为分子分母都乘了同一个 `exp(-max)`，约掉了。

**`torch.softmax` 内部就是这么实现的**，直接调用不会溢出。手写时才要记得加。

### 二分类时退化成 sigmoid

```
softmax([0, 2.5])  =  [0.0759, 0.9241]
sigmoid(2.5)       =   0.9241
1 - sigmoid(2.5)   =   0.0759
```

二分类的 softmax 和 sigmoid 是同一个东西。所以二分类通常用 sigmoid，只算一个输出，参数量和计算量都少一半。

## 为什么 softmax 回归仍然算线性模型

教材那句「尽管 softmax 是非线性函数，softmax 回归的输出仍由输入特征的仿射变换决定」，关键是**“线性”指的是决策边界，不是输出**。

softmax 是**保序**的，实测温度从 0.1 扫到 100：

| T | 第一行最大概率 | argmax 变了吗 |
|---|---|---|
| 0.1 | 1.0000 | 没变 |
| 1.0 | 0.6590 | 没变 |
| 100 | 0.3366 | 没变 |

概率从 1.0 压到 0.34，分类结果纹丝不动。

对比一个不保序的函数：

```python
z = [-3, 1, 2]              argmax = 2
softmax(z)                  argmax = 2     没变
z ** 2 = [9, 1, 4]          argmax = 0     变了
```

**区别就在这：softmax 严格单调递增，平方不是。**

决策边界的推导：类 i 赢过类 j 的条件是

```
w_i·x + b_i  >  w_j·x + b_j
(w_i - w_j)·x + (b_i - b_j) > 0
```

线性不等式，分界面是超平面。所以不管 softmax 怎么弯，决策边界永远是直的。

**什么时候它才不是线性模型**：在 `Wx + b` 和 softmax 之间插一层 relu，`W2·relu(W1x+b1)` 打断了矩阵的可合并性。

## 校准：概率准不准是另一回事

校准的定义：**所有预测为 0.5 的样本里，应该刚好一半是真的属于那个类。**

模拟 5 万个过自信的样本（logit 放大 2 倍），按预测概率分桶：

| 预测区间 | 平均置信 | 实际正类率 | 偏差 |
|---|---|---|---|
| 0.0-0.2 | 0.062 | 0.169 | +0.107 |
| 0.4-0.6 | 0.500 | 0.493 | -0.007 |
| 0.8-1.0 | 0.938 | 0.827 | -0.111 |

模型说“我有 93.8% 的把握”，实际只有 82.7% 对。说“只有 6.2% 可能”，实际 16.9%。**越往两头说得越过头。**

### 校准和准确率是独立的

```
过自信:  准确率 0.7407
校准后:  准确率 0.7407     完全没变
```

校准只改概率数值，不改谁大谁小。一个模型可以 95% 准确但严重过自信，也可以校准很好但几乎没区分能力。

### ECE

Expected Calibration Error，把概率分桶，算每桶“置信与实际的差”，按样本数加权平均：

```
ECE = Σ (n_b / n) × |该桶准确率 - 该桶平均置信|
```

上面那个模型 `ECE = 0.0967`。实际模型很少低于 0.02。

### 温度缩放

在 softmax 之前把 logits 除以温度 `T`：

```python
probs = softmax(logits / T)
```

`T > 1` 让分布更平缓。实测 `T=2` 后各桶偏差都在 0.007 内，`ECE` 从 `0.0967` 降到 `0.0040`，降了 24 倍。

`T` 是训练完在验证集上拟合的一个标量，一行代码，不改模型不重训。

### 为什么现代模型过自信

**交叉熵推着概率往极端走**：模型发现把概率推到 0.99 能进一步降 loss，就一直推。
**容量大**：参数量远超数据量时，训练集上概率饱和到接近 0/1。
**Batch norm 和 weight decay 让 logit 幅度变大**：温度缩放就是把幅度压回去。

什么时候真需要校准：要把输出概率当概率用的场景（医疗、自动驾驶、模型集成、主动学习）。纯分类任务取 argmax 的话，修不修一样。

## 交叉熵的推导

### 从似然到损失

(3.4.7) 说的是：**整个数据集的负对数似然等于每个样本损失的和。**

```
-log P(Y|X) = Σᵢ -log P(y⁽ⁱ⁾|x⁽ⁱ⁾) = Σᵢ l(y⁽ⁱ⁾, ŷ⁽ⁱ⁾)
```

第一个等号是因为样本独立，联合概率相乘，取对数变相加。第二个等号只是给每一项起个名字。

### P(y|x) = ∏ⱼ ŷⱼ^yⱼ 的含义

这个式子看着绕，其实只做一件事：**从预测分布里取出「正确答案那一类」的概率。**

三种写法结果一样：

```python
y_hat = [0.1, 0.7, 0.2]
y     = [0, 1, 0]           # 第二类

y_hat[1]              = 0.7       索引
Σⱼ yⱼ·y_hatⱼ          = 0.7       加权和
∏ⱼ y_hatⱼ^yⱼ          = 0.7       连乘幂
```

`0.1^0 × 0.7^1 × 0.2^0 = 1 × 0.7 × 1 = 0.7`，任何数的 0 次方是 1。

**为什么选连乘幂**：为了取 log 能拆开。

```
log(加权和)   = log(0.7) = -0.3567      拆不开
log(连乘幂)   = Σⱼ yⱼ·log(ŷⱼ) = -0.3567  拆成逐项相加
```

因为 `log(a×b) = log a + log b`，`log(a^b) = b·log a`。

拆成逐项相加才能求导、才能扩展到软标签、才能避免连乘下溢。

**它的来源**是多项分布的概率公式，取 n=1 单个观测、y 是 one-hot 时，系数变 1，只剩 `∏ⱼ pⱼ^yⱼ`。

### 求和里其实只有一项非零

3 分类，正确类 2：

```
logits  [2.0, 1.0, 0.1]
y_hat   [0.659, 0.242, 0.0986]
one-hot [0, 0, 1]

各项 -yⱼ·log(ŷⱼ)
  j=0: y=0, 贡献 0.0000
  j=1: y=0, 贡献 0.0000
  j=2: y=1, 贡献 2.3170
求和 = 2.317 = -log(0.0986)
```

**写成 `Σⱼ` 是为了通用性（软标签时真的会用上所有项），实现时都是一次查表。**

### 梯度是 ŷ - y

实测 autograd 的结果和手算完全一致：

```
autograd 的 grad = [ 0.659,  0.242, -0.901]
y_hat - y        = [ 0.659,  0.242, -0.901]
```

预测 0.659 的类别梯度是 +0.659，正确类预测 0.0986 的梯度是 `0.0986 - 1 = -0.901`。梯度下降时错误类被压低，正确类被抬高，差值越大修得越猛。

### 软标签（label smoothing）

```
one-hot          [0,     0,     1    ]    loss = 2.317
平滑后 0.1 比例  [0.033, 0.033, 0.933]    loss = 2.224
```

这时 `Σⱼ` 三项全非零，按 `yⱼ` 加权。作用就是防止模型过度自信，让概率不要推到 1.0，正好治前面说的校准问题。

## 化简三步与数值稳定

(3.4.9) 那三行只用了两个恒等式。

**第一步：拆 log**

```
log[ exp(oⱼ) / Σₖ exp(oₖ) ] = oⱼ - log Σₖ exp(oₖ)
```

`log(a/b) = log a - log b`，并且 `log exp(oⱼ) = oⱼ`，exp 被消掉。

代回去整理得到：

```
l = Σⱼ yⱼ log Σₖ exp(oₖ) - Σⱼ yⱼ oⱼ
```

**第二步：提出常数**

`log Σₖ exp(oₖ)` 只跟 k 有关，**跟 j 无关**，对每一项都是同一个常数，可以提到求和外面：

```
Σⱼ yⱼ · C = C · Σⱼ yⱼ = C × 1 = C
```

`Σⱼ yⱼ = 1`，one-hot 只有一个 1，软标签各分量和为 1。所以：

```
l = log Σₖ exp(oₖ) - Σⱼ yⱼ oⱼ
```

四个形式实测都是 `2.317030`，和 `F.cross_entropy` 一致。

**为什么化简：数值上原始式会崩。**

```
o = [1000, 999, 998]
手动 softmax  →  [nan, nan, nan]
logsumexp     →  1000.41
l = 1000.41 - 1000 = 0.4076     和理论值 log(1+e⁻¹+e⁻²) 一致
```

第三行的 `log Σₖ exp(oₖ)` 可以整体用 logsumexp 算（内部先减最大值），不需要单独算每个 `exp`。

**PyTorch 的 `cross_entropy` 内部就是这样：先 log_softmax，再取负号乘标签。**

## 惊异、熵、交叉熵

教材说可以从两方面看交叉熵：最大化似然，或最小化惊异。这是同一件事的两种说法，因为 `-log` 单调递减。

### 惊异 = -log p

| 概率 p | 惊异 | 直觉 |
|---|---|---|
| 1.0 | 0.000 | 必然发生，完全不惊讶 |
| 0.5 | 0.693 | 一半一半 |
| 0.1 | 2.303 | 少见 |
| 0.01 | 4.605 | 罕见 |

也叫自信息，信息论的基本单位。

### 熵是平均惊异

```
H(p) = -Σⱼ pⱼ log pⱼ
```

`p = [0.7, 0.2, 0.1]` 时：

```
j=1: 0.7 × log(0.7)    = 0.7 × (-0.3567) = -0.2497
j=2: 0.2 × log(0.2)    = 0.2 × (-1.6094) = -0.3219
j=3: 0.1 × log(0.1)    = 0.1 × (-2.3026) = -0.2303
Σ = -0.8018，取负号 H(p) = 0.8018
```

含义：用最优编码传递这些事件，每个平均要多少 nat。

### 交叉熵是用错的分布编码

```
H(p, q) = -Σⱼ pⱼ log qⱼ
```

`q` 是模型的预测分布：

```
j=1: 0.7 × log(0.6)    = 0.7 × (-0.5108) = -0.3576
j=2: 0.2 × log(0.3)    = 0.2 × (-1.2040) = -0.2408
j=3: 0.1 × log(0.1)    = 0.1 × (-2.3026) = -0.2303
Σ = -0.8286，取负号 H(p,q) = 0.8286
```

### 三者关系

```
H(p, q) = H(p) + KL(p‖q)

KL(p‖q) = Σ pⱼ log(pⱼ/qⱼ)
        = 0.1079 + (-0.0811) + 0 = 0.0268
```

验证：`0.8018 + 0.0268 = 0.8286` ✓

展开证明是代数上必然：

```
H(p) + KL = -Σ p log p + Σ p log(p/q)
          = Σ p [-log p + log p - log q]
          = -Σ p log q
          = H(p, q)
```

注意 KL 的每一项可以是**负的**（`q₂ > p₂` 时那一项在省码长），但总和一定非负（吉布斯不等式）。

**因为 H(p) 是常数**（真实分布固定，跟模型无关），所以：

```
最小化交叉熵  ⟺  最小化 KL  ⟺  让 q 逼近 p
```

`q` 和 `p` 完全相同时，`KL = 0`，`H(p,p) = H(p) = 0.8018`。**交叉熵的地板就是熵。**

### 单位

```
以 e 为底（nat）: 0.8018
以 2 为底（bit）: 1.1568
换算：nat × 1.4427 = bit
```

教材用 `e` 因为求导干净。论文里报语言模型效果常用 bit 和困惑度（`perplexity = exp(交叉熵)`）。

## axis 为什么是按行还是按列

`axis=k` 指的是**被消掉的那一维**，也是**沿着它遍历的方向**。

```
(2,3) argmax(axis=1) → (2,)     消掉 3，剩 2
(2,3) argmax(axis=0) → (3,)     消掉 2，剩 3
```

**结果有几个数，这些数属于谁，决定了“按行”还是“按列”。**

剩下的索引是行号，就是按行取（每行一个结果）。剩下的索引是列号，就是按列取。

不用背方向，看形状变化最快。

三维时更明显：`(2,3,4)` 按 axis=1 得到 `(2,4)`，中间那个 3 消失。

## 从零实现里的几个函数

### accuracy

```python
def accuracy(y_hat, y):
    if len(y_hat.shape) > 1 and y_hat.shape[1] > 1:
        y_hat = y_hat.argmax(axis=1)
    cmp = y_hat.type(y.dtype) == y
    return float(cmp.type(y.dtype).sum())
```

5 个样本走一遍：

| 步骤 | 结果 | dtype |
|---|---|---|
| `argmax(axis=1)` | `[2, 2, 0, 1, 0]` | int64 |
| `== y` | `[F, T, F, T, T]` | bool |
| `.type(y.dtype)` | `[0, 1, 0, 1, 1]` | int64 |
| `.sum()` | `3` | int64 |
| `float(...)` | `3.0` | float |

返回的是**对了几个**，不是比例。要准确率得自己除。

两次 `type` 转换：第一次对齐类型（`argmax` 是 int64，标签可能是别的整数类型），第二次把 bool 转成 0/1。

**这个函数在二分类时是错的。** `shape[1] == 1` 时跳过 argmax，直接比较 `(3,1)` 和 `(3,)`，会广播成 `(3,3)`：

```
y_hat [[0.8],[0.3],[0.6]]   标签 [1,0,0]   正确答案 2 个
转整数后 [0,0,0]（0.8 截断成 0）
广播比较 sum = 6        ← 多算三倍，不报错
```

正确做法：`(y_hat.reshape(-1) > 0.5).long()` 再比。**只在多分类时能直接用。**

### evaluate_accuracy

```python
def evaluate_accuracy(net, data_iter):
    if isinstance(net, torch.nn.Module):
        net.eval()
    metric = Accumulator(2)
    with torch.no_grad():
        for X, y in data_iter:
            metric.add(accuracy(net(X), y), y.numel())
    return metric[0] / metric[1]
```

`net.eval()` 的作用，用带 Dropout 的网络实测：

```
train 模式两次输出: [-0.830, -0.093] / [-0.846, -0.569]    不一样
eval  模式两次输出: [-0.657, -0.071] / [-0.657, -0.071]    一样
```

Dropout 训练时随机丢，评估时必须关掉。纯线性层没有 Dropout，两模式无差别，但第 7 章学 BatchNorm 后就必须切。

**为什么最后才除**：假设 3 个 batch 正确率 `[0.9, 0.8, 1.0]`，样本数 `[256, 256, 16]`：

```
每个 batch 比例直接平均  : 0.9000
对的总数 / 样本总数      : 0.8545
```

差 4.5 个百分点。最后一批只有 16 个，却被当成同等权重。正确做法是累计个数，最后除一次。

### Accumulator.add

```python
def add(self, *args):
    self.data = [a + float(b) for a, b in zip(self.data, args)]
```

三个部件：`*args` 收成元组、`zip` 配对、列表推导逐对相加。

```
data = [0.0, 0.0]  args = (3, 10)
zip → [(0.0, 3), (0.0, 10)]
结果 → [3.0, 10.0]
```

`float(b)` 必须有，因为 `b` 可能是张量：

```
0.0 + tensor(3)        → tensor(3.)     类型 Tensor
0.0 + float(tensor(3)) → 3.0            类型 float
```

不转的话 `self.data` 会混进张量，后面除法出问题。

**隐患**：`zip` 按短的截断。`Accumulator(3)` 却 `add(1, 2)`，槽位会从 3 变成 2，之后 `metric[2]` 报 `IndexError`。

### train_epoch_ch3 的两条分支

```python
if isinstance(updater, torch.optim.Optimizer):
    updater.zero_grad()
    l.mean().backward()
    updater.step()
else:
    l.sum().backward()
    updater(X.shape[0])
```

**为什么一个 mean 一个 sum**：`torch.optim.SGD` 直接按梯度走（`w -= lr * grad`），必须先变成平均梯度。手写 `sgd` 内部会 `/ batch_size`，所以传总梯度。

数学上等价：

```
d(mean)/dw = d(sum)/dw / bs
内置：w -= lr × d(mean)/dw = w - lr × d(sum)/dw / bs
手写：w -= lr × d(sum)/dw / bs
```

实测两条路径各跑一轮，`train_loss` 0.7861 对 0.7853，差异来自 shuffle 顺序不同，不是算法。

**累加的是 `l.sum()` 不是 `l.mean()`**，因为要算整轮真实平均：`总loss / 总样本数`。换成 `l.mean()` 会小 256 倍。

## 简洁实现

### Flatten 不能省

`nn.Linear` 只认二维 `(batch, features)`。直接喂四维：

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (7168x28 and 784x10)
```

那个 `7168x28` 是这样来的：**Linear 只看最后一维，前面全当 batch**。

```
(256,1,28,28) → Linear 理解成 (7168, 28)
```

`nn.Flatten()` 等价于 `x.reshape(x.shape[0], -1)`，默认 `start_dim=1` 保留 batch。实测两者结果完全一致。

### init_weights 与 apply

```python
def init_weights(m):
    if type(m) == nn.Linear:
        nn.init.normal_(m.weight, std=0.01)

net.apply(init_weights)
```

三个细节：

**用 `type(m) == nn.Linear` 而非 `isinstance`**，精确匹配，不误伤继承了 Linear 的自定义层。

**`nn.init.normal_` 的下划线表示原地修改**，不用再赋值回去。

**bias 没被初始化。** 实测：

```
weight: std 0.0207  →  0.0102      改成 0.01
bias  : std 0.0147  →  0.0147      没变
```

教材只改 weight，bias 保留 `nn.Linear` 自带的 uniform 初始化。3.2 手写版是全零，两种都能收敛。

`net.apply` 递归遍历所有子模块，顺序是子模块先父模块后：

```
访问 Flatten      ← 跳过，类型不对
访问 Linear       ← 处理
访问 Sequential   ← 容器自己也被访问
```

### CrossEntropyLoss 的 reduction

```python
loss = nn.CrossEntropyLoss(reduction='none')
```

三种返回：

| reduction | 形状 | sum | mean |
|---|---|---|---|
| `none` | `(256,)` | 702.22 | 2.7430 |
| `mean` | `()` | 2.74 | 2.7430 |
| `sum` | `()` | 702.22 | 702.2180 |

**必须用 none**，因为 `train_epoch_ch3` 要两种操作：

```python
l.mean().backward()             # 反向用平均
metric.add(float(l.sum()), ...)  # 统计用总和
```

`l` 是向量时两者不同；是标量时 `mean()` 和 `sum()` 都返回它自己，总和的信息永久丢失。

用默认 reduction 实测：

```
reduction='none'   train_loss 0.7869   train_acc 0.7486
默认 reduction      train_loss 0.0031   train_acc 0.7486
```

**loss 差 256 倍，准确率完全一样。** 因为梯度用的是 `l.mean()`，标量时它等于自己，梯度正确，模型学得一样好。错的只是统计：累加了「每批平均 loss」，却除以「总样本数 60000」，分母放大 256 倍。

这是最难发现的那类 bug：训练正常、曲线照降、只有数值不对。

**自己写循环只做 `l.backward()` 的话，用默认的 mean 就行**，不需要 none。

## 概念清单

### 网络结构

| 概念 | 含义 |
|---|---|
| 全连接层 | 每个输出都连接到所有输入，数学上是 `y = Wx + b`。也叫 Linear、dense、仿射层 |
| 参数量 | 全连接层为 `输入维 × 输出维 + 输出维`。784→10 是 7850 个，4096→4096 是 1678 万个 |
| 局部连接 | 每个输出只连输入的一小块，卷积层就是这样。784→10 若只连 28 个，参数量从 7840 降到 280 |
| `nn.Flatten` | 把 `(N,1,28,28)` 展平成 `(N,784)`，等价 `x.reshape(x.shape[0], -1)`。默认 start_dim=1 保留 batch |

### 概率输出

| 概念 | 含义 |
|---|---|
| softmax | `softmax(z)ᵢ = exp(zᵢ) / Σⱼ exp(zⱼ)`。输出全正、和为 1、保持大小顺序 |
| logits | softmax 之前的原始分数，可以是任意实数。模型最后一层通常直接输出 logits |
| 校准 calibration | 预测概率等于实际频率。所有预测 0.8 的样本里应该真有 80% 是对的 |
| 过自信 | 预测概率比实际准确率高。深度模型普遍如此，因为交叉熵推着概率往极端走 |
| ECE | `Σ (n_b/n) × abs(准确率_b - 置信度_b)`，分桶加权平均。实际模型很少低于 0.02 |
| 温度缩放 | `softmax(logits / T)`。T>1 让分布更平缓，降低置信度。实测 ECE 从 0.0967 降到 0.0040 |
| sigmoid 与 softmax | 二分类时 `softmax([0,x])` 等于 `[1-sigmoid(x), sigmoid(x)]`，所以二分类用 sigmoid 更省 |

### 损失函数

| 概念 | 含义 |
|---|---|
| 交叉熵 | `H(p,q) = -Σⱼ pⱼ log qⱼ`。p 是真实标签分布，q 是预测分布 |
| `P(y∣x) = ∏ⱼ ŷⱼ^yⱼ` | 取出正确类概率的写法。one-hot 时退化成 `ŷ[正确类]`，选它是因为取 log 能拆成求和 |
| 梯度 ŷ - y | softmax 加交叉熵的梯度。预测 0.659 的类梯度 +0.659，正确类预测 0.0986 梯度 -0.901 |
| label smoothing | 把 one-hot 换成软标签（如 0.9 给正确类、0.1 均分给其余）。防止过度自信，改善校准 |
| logsumexp | 稳定计算 `log Σ exp(x)` 的方法，内部先减最大值。`cross_entropy` 内部用它避免溢出 |
| 惊异（自信息） | `-log p`。p=1 时为 0，p=0.01 时为 4.605。概率越小越惊讶 |
| 熵 | `H(p) = -Σ p log p`，平均惊异，也是最优编码的平均码长。`[0.7,0.2,0.1]` 的熵是 0.8018 |
| KL 散度 | `KL(p‖q) = Σ p log(p/q)`，用错分布编码多花的码长。恒非负，p=q 时为 0 |
| 交叉熵的分解 | `H(p,q) = H(p) + KL(p‖q)`。H(p) 是常数，所以最小化交叉熵等价于最小化 KL |
| reduction | 损失的归约方式。`none` 保留逐样本 `(256,)`，`mean` 给平均标量，`sum` 给总和标量 |

### 训练实现

| 概念 | 含义 |
|---|---|
| eval / train 模式 | `net.eval()` 关掉 Dropout 和 BatchNorm 的随机性。实测 Dropout 网络 train 模式两次输出不同，eval 模式相同 |
| Accumulator | 累加多个指标。`Accumulator(2)` 两个槽位，`add(正确数, 总数)`，最后相除 |
| 为什么最后除 | 3 个 batch 正确率 `[0.9,0.8,1.0]` 样本数 `[256,256,16]`，按批平均得 0.9000，按总数除得 0.8545，差 4.5 个百分点 |
| `net.apply` | 递归遍历所有子模块应用函数，顺序是子模块先父模块后 |
| 梯度累加 | `backward()` 执行 `grad += 新梯度`，所以每轮必须 `zero_grad()`，否则等效学习率随步数上涨 |
